# Handwrite-Recognization

## Handwritten Character Recognition Using CNN

An interactive Streamlit application that classifies one handwritten digit or
English letter from a drawing or uploaded image. Predictions come from a trained
PyTorch convolutional neural network (CNN) using the 47-class EMNIST Balanced
dataset; the app does not train the model when it starts.

## Problem Statement

Handwritten characters vary in shape, size, and stroke thickness. This project
uses a CNN to learn visual patterns from labeled examples and predict which of
47 supported characters most likely appears in a user-provided image.

## Objectives

- Train and evaluate a CNN on EMNIST Balanced, keeping the test set separate
  from training.
- Recognize handwritten digits and letters from a drawing canvas or PNG/JPG.
- Show the predicted character, its confidence, and the top three predictions.
- Display measured training/evaluation results and performance plots.
- Keep training, inference, preprocessing, and the UI in separate modules.

## Application Features

- Draw a character using a white brush on a dark canvas; change brush size or
  clear and retry.
- Upload PNG or JPG images with either a light or dark background.
- Inspect the original image and the normalized 28x28 input used for inference.
- View top-three class probabilities.
- Review measured metrics, accuracy/loss plots, a 47-class confusion matrix,
  and the classification report.
- Run on CPU, or automatically use CUDA when available.

## Dataset and Labels

EMNIST Balanced provides 47 classes: digits `0`-`9`, uppercase `A`-`Z`, and
the case-sensitive lowercase labels `abdefghnqrt`. The class order is defined
in [`utils/labels.py`](./utils/labels.py) and is used by training, evaluation,
and prediction.

Torchvision downloads the dataset into `data/EMNIST/`. The project transposes
the stored EMNIST images to display characters upright. The training split has
112,800 examples and is divided into training and validation subsets. The
separate test split has 18,800 examples and is reserved for final evaluation.
Downloaded data is local and excluded from Git.

## CNN Architecture

Input images are grayscale, 28x28 pixels, normalized to `[-1, 1]`.

1. Convolution, 1 to 32 channels, 3x3 kernel, padding 1
2. ReLU and 2x2 max pooling
3. Convolution, 32 to 64 channels, 3x3 kernel, padding 1
4. ReLU and 2x2 max pooling
5. Flatten 64x7x7 features
6. Fully connected layer with 128 units, ReLU, and 25% dropout
7. Fully connected output layer with 47 logits

Training uses cross-entropy loss and Adam with a learning rate of `0.001`.
Defaults are 10 epochs, batch size 128, validation fraction 0.1, and seed 42.
During training only, 15% of each batch is randomly thickened and another 15%
thinned to improve robustness to different handwriting stroke widths. Validation
and prediction inputs are not augmented. The best validation checkpoint is
saved to `model/trained_model.pth`.

## Image Preprocessing

[`utils/preprocessing.py`](./utils/preprocessing.py) handles uploaded images and
canvas RGBA arrays through one shared pipeline:

1. Convert to RGB and grayscale.
2. Apply light denoising and detect whether the background should be inverted.
3. Threshold the character, remove small connected components, and reject blank
   inputs.
4. Crop and scale the character to fit within a 20x20 area, center it on a
   28x28 canvas, and normalize it to `[-1, 1]`.

The same preprocessing function is used for EMNIST training and validation,
the held-out test split, and interactive inference. This is important: training
on raw normalized EMNIST images while thresholding and recentering only at
prediction time creates a distribution mismatch and can sharply reduce
real-world accuracy.

## Measured Model Performance

These are measured outputs from the preprocessing-aligned, stroke-width-
augmented checkpoint, not hard-coded estimates:

- Best validation accuracy: **87.05%**
- Held-out test accuracy: **86.46%** across **18,800** samples
- Macro precision: **86.54%**; macro recall: **86.46%**; macro F1: **86.27%**
- Uppercase `B` recall: **95.75%** (383 of 400 examples)
- Digit `7` recall: **98.25%** (393 of 400 examples); **2 of 400** sevens
  were classified as `T`.

The full per-class report and confusion matrix are saved in
[`results/evaluation.json`](./results/evaluation.json). The training history
and charts are generated by the training and evaluation scripts. The Streamlit
dashboard reads these files and displays their values.

On the original high-resolution upload that previously predicted `F` at 32.21%,
the updated model predicts `B` at **99.15%**. Stroke-width augmentation changed
the held-out score from **86.75%** to **86.46%** (a 0.29 percentage-point
decrease), while improving this thin-stroke example. The earlier preprocessing
mismatch had reduced the original checkpoint to **78.88%** when test images
used the application's inference preprocessing; aligning those pipelines
restored the score to **86.75%** before the new augmentation. The pre-fix model
scored 87.18% only when test images used the old training-only transform; that
higher number did not represent the input distribution seen by the app. See
[`results/model_debug_comparison.json`](./results/model_debug_comparison.json)
for the measured preprocessing and thin-stroke comparisons.

## Setup on Windows

Open PowerShell in the project directory and create a Python 3.11 environment:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell prevents environment activation, either adjust the execution policy
for your user or run the commands below with the virtual-environment Python
executable directly, for example:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Train the Model

From the project directory:

```powershell
python -m training.train
```

The command downloads EMNIST Balanced if needed, trains on the training subset,
validates on a separate validation subset, saves the best model checkpoint and
training history, and generates the accuracy and loss plots. It automatically
selects CUDA when available and otherwise uses CPU.

Training options can be overridden:

```powershell
python -m training.train --epochs 10 --batch-size 128 --learning-rate 0.001 --validation-fraction 0.1 --seed 42
```

To fine-tune existing weights after preprocessing or training changes, provide
an initial checkpoint. The trainer evaluates it on the validation split first
and keeps whichever checkpoint achieves the best validation accuracy:

```powershell
python -m training.train --epochs 3 --batch-size 128 --learning-rate 0.0003 --initial-checkpoint model/trained_model.pth
```

## Evaluate the Model

Run evaluation separately on the held-out test split:

```powershell
python -m training.evaluate
```

This writes measured accuracy, sample count, classification report, and
confusion matrix data to `results/evaluation.json`, and generates
`results/confusion_matrix.png`. The test split is not used for training.

## Run the Application

```powershell
streamlit run app.py
```

Open the local URL printed by Streamlit, usually
`http://localhost:8501`. Inference loads the saved weights once and does not
retrain the CNN. If the checkpoint is missing, the app reports the problem;
run the training command to create it.

## Run Tests

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

The tests cover the model and local dataset, preprocessing edge cases,
checkpoint inference, top-three output, and Streamlit dashboard/performance
data. The EMNIST loading test is skipped if the dataset has not been downloaded;
the other tests use the included model and result files.

## Upload to GitHub

1. Create a new **empty** public repository on GitHub (do not initialize it
   with a README or license).
2. In PowerShell, open the project directory and run:

   ```powershell
   git init
   git add .
   git status --short
   git commit -m "Initial handwritten character recognition project"
   git branch -M main
   git remote add origin https://github.com/<USERNAME>/<REPOSITORY>.git
   git push -u origin main
   ```

3. Replace `<USERNAME>` and `<REPOSITORY>` with your repository details.
   Authenticate through Git Credential Manager or GitHub's recommended
   sign-in flow; never put a password or access token in source files or the
   remote URL.
4. Before pushing, confirm `data/`, `.venv/`, and `.streamlit/secrets.toml` do
   not appear in `git status`. The trained checkpoint and small `results/`
   artifacts should remain in the repository because the app uses them.

## Deploy to Streamlit Community Cloud

1. Push the public GitHub repository using the steps above.
2. Sign in to Streamlit Community Cloud and choose **Create app**.
3. Select the repository, `main` branch, and `app.py` as the main file.
4. Select Python 3.11 in the advanced settings, then deploy.
5. Check the deployment logs if dependency installation or startup fails.

The repository includes `model/trained_model.pth`, the evaluation outputs, the
plots, and `requirements.txt`, so the deployed app can start without the local
EMNIST dataset or a training run. Do not upload `.venv/`, `data/`, or secrets.
